### D2 — Car routing engine (a spike in P2a, decided at the stop)

- **Question:** can r5py take per-link, per-period, per-direction speeds cleanly?
- **Option A — r5py.** Build per-period OSM extracts with edited `maxspeed` (and
  `maxspeed:forward`/`:backward`). Test on ~20 ways whether R5 honours the edits in
  both directions.
- **Option B — OSRM.** Use upstream's OSRM toolchain with per-period segment speed files
  (`osrm-customize --segment-speed-file`). This is directional by node pair, which
  suits a directional factor table. Note: upstream runs OSRM in Docker (its own
  `docker run` with `hostport:5000`, working around a depot port bug), so B adds a
  Docker dependency to the lab. Record it in `sources.md` and the run record.
- **Recommendation:** B, unless A passes the direction test cleanly. Walk, cycle and PT
  stay in R5 either way.
- **Port:** don't use 5000 (upstream finding: macOS AirPlay owns it); probe for a free
  port.

### D3 — Routing points and skim grain

- **Origins:** OA population-weighted centroids inside the extent (**3,799**). Also
  used for OA accessibility.
- **Destinations:** LSOA points (**729**). Default: the LSOA population-weighted
  centroid (already in `lsoa_pwc` / `int_lsoa`).
  - Measure in the spike whether a job-weighted LSOA point changes HBW times materially.
    If it does, use it for HBW destinations.
- **Why this grain:** routing OA → LSOA (3,799 × 729 ≈ 2.77M pairs per mode and
  period) serves both the LSOA → LSOA skims and OA-level accessibility.
- **LSOA → LSOA skims:** origin OAs aggregated with population weights. Compute GC per OA
  pair first, then take the weighted mean (not the GC of mean times).
- **Runtime:** estimate the full PT skim cost (with the 60-minute window and
  percentiles) from a 1% sample, as upstream did for OSRM, before committing to it.

### D4 — Area types

- **Urban/rural:** from the ONS 2021 rural–urban classification [SOURCED]. Confirm it
  exists at OA or LSOA level and record the version. Confirm whether it covers Wales.
- **Centre:** a subset of urban. LSOAs above a job-density threshold [MODELLED],
  producing a small number of contiguous centres (Bristol, Bath, perhaps Weston).
  Store the resulting zone list in config and plot it for review.

### D5 — Road classes and the SRN

- **Classes:** motorway/trunk (SRN), primary, secondary, tertiary and below, from OSM
  `highway`.
- **SRN links:** identified from OSM `motorway`/`trunk`, cross-checked against National
  Highways' published SRN network if a licensable copy exists.
- **Local A roads:** DfT's measure covers A roads managed by local highway authorities,
  so it excludes the SRN. Map to that definition via OSM `ref` beginning "A" and not on
  the SRN, and record mismatches.
- **Wales:** the M4 and A-road trunk network in Wales is run by the Welsh Government,
  not National Highways, and DfT's local-road measures cover England. See D8.

### D6 — Direction

- Inbound or outbound relative to the nearest centre (D4): a way is inbound if
  traversing it reduces distance to that centre.
- Each centre's coordinates are data, so they live in config.

### D7 — PT cost components (new)

- **Finding:** r5py 1.1.7's `TravelTimeMatrix` returns only total travel time at the
  requested percentiles (`travel_time_p25/p50/p75`). There is no walk / wait / IVT /
  transfer breakdown. `DetailedItineraries` returns legs, but for single departure
  times, and it is much slower.
- **Proposed default:**
  - total times from `TravelTimeMatrix` at OA → LSOA, 60-minute window,
    p25/p50/p75;
  - components from `DetailedItineraries` on LSOA-PWC → LSOA-PWC pairs (729² ≈ 531k),
    at a small number of departure times spread across the window (e.g. 3), for the
    fastest itinerary at each;
  - GC per pair = total p50 + (w_walk − 1)·walk + (w_wait − 1)·wait +
    n_transfers·P_interchange, using the component mix from the itinerary sample.
    This is an approximation, and it's recorded as one.
- **Alternatives, if A8 shows the itinerary run is too slow:** components for a
  stratified sample of pairs only, with a fitted model of components against total time
  and distance; or calling R5's Java API directly for path details (more work, and it
  bypasses r5py). Decide on the A8 measurements.

### D8 — Newport masking and Welsh car speeds (was §3.4)

- **Mask:** `mask.lads` in config: `W06000022` Newport and `W06000021` Monmouthshire.
  These cover all 69 internal Welsh LSOAs. They're excluded from PT accessibility
  metrics, the DfT comparison and the gap map, shown as hatched "no bus data", not as
  low access. Rail and walk still route through them.
- **Car speeds in Wales have no calibration data** (new finding). BODS covers England
  only, so there are no Welsh bus positions. DfT local-road speeds are England only,
  and WebTRIS covers only the National Highways network in England. Car skims for
  Newport-area zones are still needed (gap map masked, but P5 mode choice and
  cross-border car trips need them).
- **Decided (Robbie, 2026-09-27):** apply the fitted factors for the same road class ×
  area type × direction from the English side, tagged `[MODELLED]`, and list it in
  reports. Check
  in A7 whether the Welsh Government or Traffic Wales publishes usable trunk-road
  speeds; if so, use them on the Welsh M4/A48 as validation.

## 5. P2b — Congestion calibration and validation

### Model

```
car link time = free-flow time × factor[period][direction][road_class][area_type]
```

- Periods: AM and IP now, with the PM parameters fitted but unused.
- **The calibration target is absolute speed.** DfT reports average speeds, so fit
  modelled speeds to them directly; the factor is how the fit is represented.
- **Free-flow speed:** OSM `maxspeed` where tagged, else the defaults of the chosen
  engine. Record the share of links with tagged limits.

### Data processing

**B1 — Bus-lane and busway exclusion list.**
- Ways tagged `highway=busway`, `busway=*`, `bus:lanes=*`, `lanes:bus=*`,
  `lanes:psv=*`, `psv=designated` lanes.
- Plus the Metrobus guided and segregated sections: Metrobus services are identified by
  the route IDs in config, and their shapes are matched to OSM.
- Also flag a link if it is part-lane, since part of its length may still be shared.
- Plot the list for review.

**B2 — Vehicle-location processing.**
- **Map-matching:** match positions to OSM ways (OSRM `/match`, or a lightweight HMM
  matcher, decided on quality).
- **Speeds:** compute moving speeds per way traversal. Drop positions within
  `stop_buffer_m` of a GTFS stop and positions below `min_moving_kmh`.
- **Exclusions:** drop excluded ways (B1) and part-lane links.
- **Aggregation:** by way × direction × period over neutral weekdays. Keep a way only if
  it has at least `min_obs_per_link` traversals.
- **Report:**
  - coverage by road class and area type;
  - the share of each local highway authority's A-road length covered by kept bus
    data.

**B3 — WebTRIS processing.** Mean speed by site × direction × period, flow-weighted
within period. Map each site to its SRN way section.

### Fit

- **Motorway/trunk:** fitted directly to WebTRIS by period and direction. Where a
  section has no site, interpolate between neighbouring sites along the same road;
  otherwise use the class mean.
- **Local A roads:**
  - **Constraint:** fit so each local highway authority's modelled, flow-weighted
    (AADF) average local-A-road speed matches the DfT figure for each period and the
    urban/rural split. Compute it like-for-like with DfT's own definition. (If A7 finds
    the table is coarser, the constraint uses whatever grain DfT publishes, and bus
    data carries more of the period/area split. Decided at the P2a stop.)
  - **Shape:** filtered bus moving speeds shape the relative pattern between area types
    and directions *within* each authority, as a soft term.
- **Minor roads (tertiary and below):** bus-derived where coverage exists. Elsewhere,
  a `[MODELLED]` ratio to the local A-road factor for the same area type, direction and
  period, with the reasoning recorded.
- **Wales:** transferred factors (D8).
- **Parsimony:** keep the parameter count well below the number of independent targets,
  and regularise towards the class mean where data is thin. Report the count.
- **Recovery test:** fitted parameters are written to `params/` as `[CALIBRATED]`, with
  target and fit. Before that, a synthetic test must recover known factors.

### Build car skims

- Apply the fitted speeds in the engine chosen in D2.
- Produce AM and IP car times for the D3 point sets.
- **Car GC in P2** = in-vehicle time + parking search + access walk, all by destination
  area type (`[PLACEHOLDER]` until sourced; flagged in outputs).

### Validation on held-out data

- **Hold-out design:** calibration uses DfT and WebTRIS only. Bus data is used for shape
  on a **spatially blocked** fit set: hold out whole corridors, not random links, to
  avoid leakage.
- **Validate against:**
  - held-out bus moving speeds;
  - Historic journey times, if usable (relative pattern only if pre-2020);
  - ATC speeds, when they arrive (as a re-run: `lab congestion calibrate --validate`
    reads an optional ATC input, so adding it later changes no code).
- **Report distributions, not just means:** median, p10 and p90 of modelled ÷ observed,
  by area type, road class and period. Include a map of residuals.
- **Car spot checks:** 20 OD pairs spanning centre, radial, orbital and inter-urban
  routes (e.g. Bath → Bristol), compared against observed route times from the held-out
  sources where they exist.
- **Timetable vs observed:** a report of GTFS scheduled bus running times against
  observed ones, by route and period. It's informational and feeds the §12 reliability
  item. Timetables are not changed in v1.

### Outputs

- A `link_speed(period, osm_way_id, direction, speed_kmh, factor, source, tag)` table.
- Car skims per period.
- A congestion-factor map (AM, centre vs suburbs) as GeoParquet and PNG. It's a
  candidate blog graphic.
- A calibration and validation report in `runs/<run_id>/`.

### Acceptance (P2b stop)

Tolerances are `[MODELLED]` starting points.
- Each authority × period local-A-road modelled speed is within ±5% of DfT (at the
  grain DfT publishes).
- SRN period-direction speeds are within ±10% of WebTRIS at site level, median.
- Held-out bus moving-speed error: median |error| ≤ 15%, with the distribution reported.
- Car spot checks: at least 16 of 20 within ±15%. Each failure is explained.
- The synthetic recovery test passes.

## 6. P2c — Skims, accessibility, spot checks and draft gap map

### C1 — Skims (SPEC §4 schema, partitioned Parquet)

- **PT:** r5py AM and IP, 60-minute departure window, p25/p50/p75 totals from
  `TravelTimeMatrix`. Components (walk, wait, IVT, transfers) from the D7 method, not
  from the full matrix. `fare_gbp` is null in P2.
- **Walk and cycle:** r5py. For cycling, record whether elevation is used and its
  source.
- **Car:** from P2b.
- **Aggregation:** OA → LSOA with population weights (D3). The gc_min column is the
  time-based GC from SPEC §7.2 with the P2 weights. Mark it provisional until the
  PLACEHOLDER weights are sourced.
- **Sanity checks:**
  - no negative or zero times off the diagonal;
  - symmetric-ish walk and cycle times;
  - PT unreachable pairs counted and mapped.

### C2 — Accessibility

- **Measures:**
  - cumulative: BRES jobs (undiscounted; these are opportunities, not trips) reachable
    within 30 and 45 minutes by PT, AM, p50, per OA;
  - decay-weighted, with β `[PLACEHOLDER]`;
  - the same measures for walk and car, for context.
- **Edge effect** (new): destinations are internal LSOAs only, so OAs near the boundary
  under-count reachable jobs against the DfT metric, which counts everything.
  **Decided (Robbie, 2026-09-27):** for accessibility only, add external LSOAs within
  the clip buffer as opportunity destinations (BRES is national in upstream's raw
  file). They are never demand zones. Report edge OAs separately as well.
- **Newport masking:** OAs in the masked LADs are excluded from all PT accessibility
  outputs and summaries. They're shown as hatched "no bus data", not as low access.
- **Equity:** population-weighted summaries by IMD decile; record the latest IoD
  version used. (English IoD and WIMD are not comparable; Welsh OAs are masked anyway.)

### C3 — DfT Connectivity Metric comparison

- Use the release downloaded in A7.
- **Compare like with like:** pick the published measure closest to ours (a PT or
  employment connectivity score, if published separately; otherwise the overall score),
  and say which.
- **Report:** Spearman ρ at OA and at LSOA, with masked zones excluded, plus a map of
  rank differences with the largest outliers investigated.
- **Target:** ρ ≥ 0.8 (SPEC §9).

### C4 — PT spot checks (human in the loop)

- **Claude prepares** `runs/<run_id>/pt_spotchecks.csv`: 20 journeys covering radial
  bus, orbital bus, Metrobus, rail, rail + bus, Bath and Weston, with origin, destination,
  modelled date and departure time, and blank columns for the observed time.
- **Robbie** looks each journey up by hand in a public journey planner (no scraping)
  and fills in the observed times. The lookups must be for the modelled date, or the
  same weekday pattern if the planner no longer shows it.
- **Claude compares** against the model's p50: at least 16 of 20 within ±15%, with each
  failure explained.

### C5 — Draft gap map

- **Data:** HBW `p1-central`, internal rows. Daily flows weight AM skims until P4 adds
  periods.
- **Measure:** for each OD pair, the ratio of PT GC to car GC (time-based, P2 weights),
  with flow as the weight.
- **Outputs:**
  - OD-level GeoParquet;
  - an origin-LSOA summary (flow-weighted mean ratio);
  - the top 50 OD pairs by flow × ratio;
  - a static PNG for review.
- Newport pairs are masked. The label states: "time-based GC, provisional weights,
  commute only (daily flows, AM times), v1 excludes external commuters, Newport area
  masked (no Welsh bus data)".

### Tests (each written before or alongside its module)

- A calendar check that fails loudly when the modelled date is outside a feed's
  validity window.
- Darwin → GTFS on a small fixture: passing points and operational calls dropped;
  cancellations and bus replacements counted; after-midnight times kept past 24:00;
  an unmapped TIPLOC inside the buffer fails.
- Clipping keeps whole trips; de-duplication is deterministic.
- Bus-lane exclusion catches every tag variant in the list.
- Direction classification on a synthetic grid.
- Congestion fit recovers known synthetic factors.
- Aggregation weights sum to 1; GC is computed per pair before averaging.
- Masked zones never appear in PT accessibility or gap-map outputs.
- `src/` stays free of place names, line/route IDs, station codes and coordinates (new
  test; none exists yet).

## 8. Risks and open questions

| Risk | Mitigation |
|---|---|
| Full PT skim runtime or memory too high | D3's 1% projection first. Fall back to fewer percentiles or a narrower window, or to LSOA PWC origins, and record the trade-off |
| PT components unavailable at full scale (D7) | Itinerary sample, sized from the A8 timing; approximation recorded |
| BODS GTFS quality (duplicates, stale services) | A4 de-duplication report; flagged routes checked against operator timetables by eye |
| Darwin → GTFS converter errors (the lab's own code, replacing UK2GTFS) | Fixture tests; journey and call counts reconciled to the XML; Temple Meads call count cross-checked against the Monday baseline; GTFS validator |
| Modelled-date rail snapshot missed or disrupted | Capture it on the day; the Monday 28 Sep file is the fallback; check for engineering works before accepting the date |
| Vehicle-location collection gaps | Daily record counts. Extend the collection window if neutral-day coverage is short |
| Map-matching errors inflate or deflate speeds | Report match confidence. Drop low-confidence traversals and check the drop rate by area type |
| DfT road definitions don't align with OSM | D5 mismatch report; fit on the aligned subset |
| DfT local-road table coarser than assumed | Confirm in A7; the constraint uses DfT's actual grain |
| Thin bus data after the bus-lane filter in the centre | Fall back to regularised class means; report coverage honestly. The ATC data, when it arrives, targets exactly this gap |
| No car-speed data in Wales | Transferred English factors, `[MODELLED]`, listed in reports (D8) |
| pandas 3 / geopandas / r5py compatibility | Pin the versions that work; record them in `environment.lock.yml` |
